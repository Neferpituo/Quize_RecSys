- Ожидаемые сущности:
  - dataset11-30week.parquet с колонками user_id, vsetv_id (это channel_id из schedule), start_time, stop_time, duraton (опечатка в названии, читать как duration).
  - Три файла schedule с колонками channel_id, channel_title, start_time, duration, tv_show_title, tv_show_id, tv_show_category, tv_show_genre_1..3, year_of_production, director, actors. Один файл - тренировочные недели 11-20, второй - 21-30, третий - тестовые 31-42.

- Важные факты:
  - vsetv_id в view log - то же самое, что channel_id в schedule; join идет по (channel, пересечение интервалов).
  - tv_show_id = 0 - "нерелевантное ТВ", его надо исключать при построении item-каталога и анализе метаданных.
  - Тест (недели 31-42) содержит строго 5 программ на пользователя, отсортированных DESC по частоте (#1 - самая частая). Это важно для будущей метрики MAP@5.
  - **Test weeks (31-42) are strictly in the future relative to training weeks (11-30).** Согласно правилам экзамена: "Never use future viewing behaviour... The test-period schedule may be used only to know which programme airs on which channel at which time". Не используй тестовые недели для любых расчетов, кроме справочника программ.
  - Ожидаемая разметка ground-truth (из описания соревнования на Kaggle) строилась по правилу: screen_time_ratio = watched_time / show_duration, порог >= 0.8. **Важно:** В правилах экзамена этого порога нет, экзамен требует построить нормировку самому. Поэтому 0.8 здесь — это лишь один из кандидатов (candidate threshold), а не жесткое правило. В EDA не восстанавливай эти 5 программ, но включи это правило в раздел D.

D. Join quality and interaction definition
Раздел делается только на тренировочных неделях (view log и schedule 11-30).
Правило-кандидат: channel_id == vsetv_id и пересечение интервала просмотра [start_time, stop_time] с интервалом программы [schedule.start_time, schedule.start_time + duration_seconds]. Пересечение в секундах: overlap_s = max(0, min(end_v, end_p) - max(start_v, start_p))

Для порогов из INTERACTION_THRESHOLDS посчитай, применив их per-view, число просмотров с хотя бы одним совпадением и число уникальных пар (user_id, tv_show_id):
- any overlap > 0s
- overlap_s >= 30s
- overlap_s >= 60s
- overlap_s/duration >= 0.3
- overlap_s/duration >= 0.5
- overlap_s/duration_show >= 0.3
- overlap_s/duration_show >= 0.5
- overlap_s/duration_show >= 0.8 (отметь в markdown, что это порог из описания Kaggle, а не оптимальный)

Дополнительно построй вариант агрегированного правила: для пары (user_id, tv_show_id) суммарный watched_time по всем показам программы, деленный на суммарный duration_show по тем же airing'ам, порог >= 0.8, затем частота и Top-5 DESC. Выведи распределение числа item'ов на пользователя по этому правилу.
