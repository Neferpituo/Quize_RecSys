Семантика merge_overlapping_views:
Назначение: устранить двойно учет просмотров, когда пользователь смотрит один канал с нескольких устройств. Пример из данных: у одного пользователя по шоу 2400480 total_watched_s = 2 276 062 с при сумме длин эфиров 569 100 с (ровно x4). Без склейки watched_s завышен, qualified_airings считает один и тот же эфир несколько раз, aggregate_ratio маскируется через min(watched_s, show_duration)

Вход: DataFrame с колонками user_id (uint64), vsetv_id (int64), start_time (datetime64[ns]), stop_time (datetime64[ns]), duration (int64). Колонка iso_week может присутствовать - игнорировать
Выход: DataFrame с user_id, vsetv_id, start_time, stop_time, duration в таких же типах. iso_week не гарантируется, пересчитывается снаружи

Логика: для каждой пары (user_id, vsetv_id) объединить пересекающиеся интервалы [start, stop] в один: min(start), map(stop).
Пересечение - когда start_next <= stop_prev и интервалы действительно перекрываются (полные дубли, вложенные, частичные).
Касание концами (start_next == stop_prev) НЕ пересечение, два отдельных интервала

Производительности: векторизовано, без groupby.apply с циклом по пользователям. Ориентир = 5.8М строк views на 2 CPU < 30 сек, <2 GB RAM (потолок окружения - 4 GB)

Обязательные юнит-тесты (внутри модуля, pytest-стиль, с skip-маркером если pytest не установлен):
  - четыре копии одного и того же интервала - одна строка
  - 2 частично перекрывающихся интервала - одна строка
  - 2 интервала, касающихся концами - 2 строки
  - три непересекающихся интервала - три строки

4. evaluation.ipynb - новый ноутбук
Назначение: честная валидация. Никаких моделей - только 3 baseline и MAP@5 на схеме, которая будет повторена на тесте

Схема валидации:
- история = неделя 11-20
- target = недели 21-30
- пул кандидатов = уникальные tv_show_id != 0 из train_schedule_2 (export_arh_21-30-final.parquet). Обоснование: на тесте кандидатов будет ограничивать test_schedule (31-42), поэтому на валидации эмулируем это же правило - без ограничений baseline берут шоу, котрые в целевом окне не идут, и MAP искажается
- fallback единый для всех методов: глобальный топ-5 по популярности за историю, отфильтрованный пулом кандидатов. Никакие рекомендации не могут быть пустыми
- MAP@5: AP = sum_{i=1..5} (hits@i / i) / min(|gt|, 5). Пользователи с пустым gt исключаются из среднего и учитываются отдельным счетчиком n_users_eval

Структура ноутбука (каждая ячейка - отдельный смысловой шаг):

  - schedule_11_30 = concat(train_sched_core, train_sched_2), дедуп по (channel_id, start_time)
  - overlap = build_overlap_pairs(views_merged, schedule_11_30); собрать pair с колонками user_id, tv_show_id, overlap_s, view_idx, sched_idx, view_duration, show_duration
